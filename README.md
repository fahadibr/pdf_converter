# PDFForge

PDFForge converts DOC, DOCX, and plain text documents into downloadable PDFs. It is a Next.js 15 App Router application with a responsive landing page and a server-side LibreOffice conversion API.

## Features

- Drag-and-drop and keyboard-accessible file selection
- DOC, DOCX, UTF-8/UTF-16 TXT support, with extension, MIME, signature, and structural checks
- Conversion progress, retry, download, and clear-on-completion flow
- 25 MB default upload limit, PDF output size cap, and conversion timeout
- Per-process rate limiting plus Nginx request throttling
- Request-origin check, content-length limit, no-store file responses, secure response headers, and automatic temporary-file cleanup
- Light and dark color schemes, reduced-motion support, responsive layout, and server-rendered SEO metadata
- Docker Compose setup with isolated application networking and no public application port

## Technology

- Next.js 15.5, React 19, TypeScript, Tailwind CSS 3
- React Hook Form for selection and client validation
- Framer Motion for one small reduced-motion-aware state transition
- Lucide icons
- LibreOffice Writer in headless mode
- Nginx reverse proxy and Docker Compose

## Run locally

Requirements: Node.js 20.11 or newer, npm, and LibreOffice Writer (`soffice`) installed and available on `PATH`.

```bash
cp .env.example .env
npm install
npm run dev
```

Open `http://localhost:3000`. For a local production build, run `npm run build` and then `npm start`. A `package-lock.json` is generated by `npm install`; commit it with the project so future installs and image builds share the same resolved dependency tree. The Dockerfile uses `npm ci` when that lock file is present.

On macOS, install LibreOffice from the official LibreOffice download and set `LIBREOFFICE_BIN=/Applications/LibreOffice.app/Contents/MacOS/soffice` if it is not on `PATH`. On Debian or Ubuntu, install LibreOffice and common Word-compatible font fallbacks with `sudo apt-get install libreoffice-writer fonts-liberation fonts-noto-core fonts-crosextra-carlito fonts-crosextra-caladea fontconfig`.

## Environment variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | `http://localhost:3000` | Canonical origin used for metadata, sitemap, and origin validation. Set it to the public HTTPS origin before building the production image. |
| `NEXT_PUBLIC_GTM_ID` | unset | Optional Google Tag Manager container ID. Set to a valid `GTM-...` ID to load the container after page hydration. |
| `NEXT_PUBLIC_MAX_UPLOAD_MB` | `25` | Shared UI/API upload limit. Supported range is 1–25 MB; increase the Nginx body limit too if changing it. This value is public. |
| `RATE_LIMIT_WINDOW_MS` | `900000` | Per-process conversion window in milliseconds (1 minute–24 hours). |
| `RATE_LIMIT_MAX` | `10` | Per-process conversion requests per IP in the window (1–100). |
| `CONVERSION_TIMEOUT_MS` | `45000` | Maximum LibreOffice runtime per conversion (5–120 seconds). |
| `LIBREOFFICE_BIN` | `soffice` | Executable name or path for LibreOffice. |
| `SUPPORT_EMAIL` | unset | Optional address shown on the Contact page. |

Settings outside the documented bounds fall back to the defaults. Nginx currently accepts up to 26 MB of request data for the 25 MB file plus multipart overhead. If you change the file limit, update `client_max_body_size` in `nginx/conf.d/default.conf` and size the container temporary filesystem for the largest permitted request.

## Deploy on Render

The included `render.yaml` defines a Docker web service. Render builds the root `Dockerfile`, installs LibreOffice in the image, checks `/api/health`, and uses its assigned public URL for canonical metadata and upload-origin validation. The Blueprint configures the Google Tag Manager container ID for site monitoring. The service runs directly behind Render's HTTPS proxy, so Docker Compose and Nginx are not part of this deployment.

1. Push this repository to the `main` branch on GitHub.
2. In Render, choose **New → Blueprint**, connect the repository, and apply the `render.yaml` configuration.
3. Wait for the first image build and deploy. Render assigns a public `onrender.com` URL after creating the service.
4. Add `SUPPORT_EMAIL` in the service environment only if you want an address shown on the Contact page.

The Blueprint selects Render's Free web service plan so the first deployment does not incur compute charges. Free services can sleep after 15 idle minutes, may restart, and have limited memory; LibreOffice conversions of larger or complex files may need a paid instance with more memory. Temporary uploads are processed in the service's ephemeral filesystem and deleted after conversion; do not use it for persistent file storage.

## Docker Compose

The Compose setup is the recommended production path. Nginx is the only service with a published port; the Next.js/LibreOffice container has no host port and runs as the unprivileged Node user. Conversion scratch space uses a size-limited temporary filesystem. The two containers share an internal Docker network with no outbound route.

```bash
cp .env.example .env
# Edit NEXT_PUBLIC_SITE_URL to match the public HTTPS hostname before building.
docker compose up -d --build
docker compose ps
docker compose logs -f app nginx
```

The local Compose stack listens on port 80. It intentionally does not provide TLS certificates: in production, configure the ALB port 80 listener to redirect to HTTPS, terminate HTTPS at an ALB listener with an ACM certificate, and forward to the EC2 host on port 80. Do not expose the EC2 port 80 to the public internet when using this configuration; allow inbound traffic from the ALB security group only. For local-only use, port 80 may be opened on the developer machine.

The Nginx trusted-proxy configuration accepts forwarded client IPs from private network ranges. On AWS, this is safe only when the EC2 security group allows port 80 from the ALB security group. For another network topology, replace those ranges with the exact trusted proxy CIDRs.

## AWS EC2 deployment

1. Create a VPC, an Application Load Balancer, and an EC2 instance on a supported Linux distribution. Use an instance with at least 2 vCPU and 4 GiB RAM for the included LibreOffice memory limits. Encrypt the EBS volume.
2. Create an ALB HTTPS listener using an ACM certificate. Configure its target group to forward to the EC2 instance on port 80 and use `/api/health` for health checks.
3. Configure the EC2 security group to accept port 80 only from the ALB security group. Allow administrative SSH only from a controlled operator network, or use AWS Systems Manager Session Manager.
4. Install Docker Engine and the Docker Compose plugin on EC2. Clone the project, copy `.env.example` to `.env`, and set `NEXT_PUBLIC_SITE_URL` to the public `https://` origin before the first image build. Set `SUPPORT_EMAIL` if a real support address should appear.
5. Start the services with `docker compose up -d --build`. Confirm the Compose health checks pass, then point the domain at the ALB with Route 53 or your DNS provider.
6. For an update, pull the reviewed source and run `docker compose up -d --build`. Watch `docker compose logs -f app nginx` and confirm the ALB target returns healthy.

Use an instance role with no permissions unless a deployment-specific need exists. This implementation does not store uploads in S3 and does not need AWS credentials at runtime. Keep the ALB and EC2 security groups separate, enable ALB access logs if required, and set a documented retention period for infrastructure logs.

## Conversion API

`POST /api/convert` accepts one `multipart/form-data` field named `file` and returns a PDF attachment. Errors use a JSON object with an `error` and `requestId`. The API checks origin/fetch metadata, request size, rate limit, file extension, reported MIME, content signatures, DOCX package structure and expansion limits, and text encoding before starting LibreOffice. Conversion uses a unique per-request profile and temporary directory, a timeout, output size/type checks, and a `finally` cleanup.

The endpoint is a Node.js route because it starts LibreOffice as a child process. It is not suitable for an Edge runtime or a serverless platform with a read-only filesystem or short execution deadline. Always put it behind a reverse proxy or ingress that enforces a request-body cap; Nginx does this for the included deployment. The route checks `Content-Length` when provided and then checks the parsed file size as a second limit.

## Production notes

- Keep a generated `package-lock.json` in source control. Rebuild from reviewed dependency updates, run the project typecheck/linter in CI, and keep Next.js, React, Node, Nginx, LibreOffice, and base images patched.
- Next.js 15 is in Maintenance LTS; plan the move to Next.js 16 before the published security-support window ends on January 31, 2027.
- Rate limit state is process-local. Nginx throttles at the proxy and the app enforces a longer-window cap. Before running multiple app instances or hosts, move the application rate limiter to a shared store such as Redis and tune the proxy policy for the load balancer.
- Keep Nginx in front of the app. It provides the strict request body cap, client IP normalization, and edge request throttling; direct access to the app container is not published by Compose.
- LibreOffice is a large native runtime and document parsers process untrusted input. The Compose app runs as a non-root user, drops Linux capabilities, has no outbound network, limits memory/CPU, uses unique profiles, limits runtime and output size, and stores conversion files in temporary storage. Keep the image and host kernel updated.
- The API buffers the submitted multipart file and completed PDF in memory. The 25 MB input cap is intentionally conservative. For much larger files or high concurrency, move conversion to a job worker with a queue and controlled object storage lifecycle.
- CSP and other security headers are in `next.config.ts`; HTTPS is provided by the ALB. Set the real public URL before building so canonical links, Open Graph URLs, sitemap URLs, and origin checks are correct.
- The contact page needs `SUPPORT_EMAIL` configured to show an email address. Privacy and Terms pages describe the shipped file handling flow and should be reviewed for the operator's jurisdiction, retention settings, and business practices before public launch.

## SEO and accessibility

The app provides per-page metadata, canonical URLs, Open Graph and Twitter card tags, JSON-LD WebApplication data, `robots.txt`, and a sitemap. HTML is server-rendered; the Inter font is downloaded at build time and served from the app origin, with a system-font fallback. Upload controls support keyboard use and screen readers, status changes are announced, colors adapt to the operating system's dark mode, and motion is reduced when requested.
